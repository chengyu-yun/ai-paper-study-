# 阅读稿与页面格式

解释内容继续按SKILL.md中的十节结构组织。渲染器兼容上游格式，保留 `paper-reading-` 标记前缀；不要求使用上游的阅读流程或自测。

## 最小头部

```markdown
<!-- paper-reading-lang: zh-CN -->
<!-- paper-reading-theme: cobalt -->
<!-- paper-reading-mode: brief -->
# 论文名称

三句话主线。

## 1 / 问题定义

正文。
```

首行必填。主题可选 `forest`、`cobalt`、`plum`、`saffron`。普通阅读保留 `brief`；阅读深度按用户要求和解释需要决定，标记本身不能增加内容深度。`#`只放一个主标题，`##`自动生成章节导航，`###`放章节内小标题。

## 原文位置

直接写 `【原文位置：§3.2，公式2】`。渲染后可通过顶部“显示原文定位”开关查看，不让出处打断正常阅读。必须保留论文的实际定位。

## 公式

行内用 `$x=1$`，独立公式用顶层的 `$$...$$`。公式直接排版为KaTeX，不请求在线字体。先讲公式在算什么，再展示式子。

## 图片与流程图

图片放在阅读稿同目录的 `assets/` 中；渲染时会嵌入HTML，不依赖原图片路径。

```markdown
先说明这张图要看哪里，以及它回答什么问题。

![图片的中文解释](assets/fig1.png)

*原论文图1，PDF第3页。说明重点。*
```

重要流程图优先画自包含SVG：文字、模块框、带含义的箭头，不依赖在线字体或外部脚本。用同样图片语法嵌入，在正文中走一遍路径。SVG同时可作为独立流程图交付。

还可以用原生的流程卡片块，JSON字符串里不写数学标记或Markdown：

````markdown
```paper-path
{
  "title": "当前样本如何经过方法",
  "stages": [
    {
      "title": "编码观察",
      "role": "输入处理",
      "action": "用实际论文中的操作说明图像如何变成特征。",
      "why": "解释这一步解决什么问题。",
      "output": "交给下一步的表示。",
      "source": "原文§3.1"
    }
  ]
}
```
````

每个事实卡片需要 `source`；不要为了凑卡片补造论文模块。

## 折叠补充

```html
<details class="reading-detail">
<summary>展开完整推导</summary>

在此写Markdown段落、表格或公式，标签与正文之间留空行。

</details>
```

把次要推导或完整表格放在这里。理解主线必需的解释应直接展示。折叠通过浏览器原生控件工作，不需要JavaScript。

完整可运行例子见 [examples/demo/reading.md](../examples/demo/reading.md)。上游还支持全局卡片、对照、实验卡片与数据图；使用这些扩展前查看项目复用来源中的上游格式文档，普通阅读不必全部使用。
